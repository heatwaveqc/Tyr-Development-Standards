# Branch lifecycle
Search open/merged PRs, active heads/bases, issue IDs, dependencies and integrated code before branching. Reuse existing PR for coherent scope, target and owner. Transfer writer responsibility explicitly. New PR requires separate review/merge boundary, isolation/revert reason or unavoidable dependency stack; document reason. Temporary branches need accountable PR within 24h. Handoff records issue, writer, scope, paths, target, dependencies, exact SHA, checks, blockers and next action.
Designated integration writer may merge reviewed approved scope only under local delegation; inspect exact head/base, checks, collisions and dependencies; use expected head SHA. Green checks alone do not authorize merge. Keep stacks short. Freeze donors at immutable reachable commits; record successor and provenance, preserve and retarget dependencies, close fully superseded PRs without merging stale heads. Residual work needs owner, action and review date; runtime QA belongs in issue ledger.
Administrative completion includes integration/deferral and ref disposition. Review defaults: 24h no PR, 24h ready waiting, 72h inactive, 24h surviving merge, 7d unresolved donor. Age never authorizes deletion. Local permanent allowlist and budgets govern. Retirement requires independently reviewed exact branch/full SHA batch, dry run, durable preservation, live dependency checks, explicit owner approval of exact batch, lease-guarded execution and verified results. Fail closed; no dummy merges, force rewrites, scheduled pruning or retries. Normal meaningful merge head deletion only when dependencies safe. PR closure is not branch deletion.
